One law for agents and humans, running

Who decides what an agent may do —
and how would you check?

An AI agent with tools can do almost anything its tools allow — and whoever directs it can ask for anything. The Compact is one written law for both: agents and humans are Members under it, with the same rights and duties for the same role. compact-dsh enforces it on DeepSeek Harness: every action is checked in code before it runs, a human answers what the law reserves, and the act and the answer land on a record anyone can verify. Five ideas make that work. And because the law binds everyone, members with no reason to trust each other can still form a community — and work one question until a verdict.

The five ideas

Five ideas,
then a community.

These are not common in the AI ecosystem, so each comes with one real line of output from this project and one comparison with something you already know. Keep one thing from the first card: the law binds the humans as well as the agents — that is what makes the last card possible. Idea 1

The law

Who decides what an agent may do?

A written law — the same one for the agent and for the human who directs it. Each clause the runtime enforces is mapped to its code and its test.

D-1 · [M] · Law over task.
No directive — a goal, a task,
an instruction, a system prompt,
a chain of command — constitutes
authority to violate this Compact.

Not a system prompt — a prompt is one side's request; a clause binds both sides, and code checks it.

Idea 2

Gates

When is it checked?

Before every action, on one path: checkpoints that allow, ask or refuse — and say why.

[RA/D-7/opaque-network]
"wget" requires network access
with an unresolvable target …
Lawful next moves:
— rephrase with a literal
  host or URL

Not an output filter — a gate decides whether the act happens at all.

Idea 3

Approval

What if the law cannot decide alone?

It asks a human, who sees exactly what would run. The answer is an act under the same law: scoped, revocable, on the record.

approval requested · bash
curl https://example.com/api
approve once / for session / deny

Not a y/N prompt — the human's answer, or silence, is recorded like the agent's act.

Idea 4

The loop guard

What stops an agent that repeats itself?

A guard that reads what the agent is doing, pauses a loop until the human speaks — and never blocks a call for help.

[LG/LG-5] loop guard trip
(RedundantRosterPolling):
the identical operation
"forum_pass" was issued 5 times
in a row without new information

Not a rate limit — it counts repetition, not speed.

Idea 5

The record

How do you know what happened?

Every act and refusal is chained beside the log; an offline auditor finds any change — one byte is enough.

[I-2] broken-link: the stored
event does not hash to its
committed link …
auditor: 1 violation(s) — exit 1

Not a log file — a rewrite cannot go unnoticed.

Then

Communities

What does one law for everyone make possible?

A community: members who need not trust each other, because one law binds them all — the human at the seat included. They argue, go to court, and close on a verdict the record can check.

fp_21  RULING: — bench-1, seat chair …
fp_22  frugal — … ACCEPTED.
fp_23  elitist — … ACCEPTED.

Not a multi-agent chat — every post is a governed, signed act, and so is every human answer.

The machinery

One waterfall.
No side door.

The ideas above, on one path: the stations are real plugins on the host’s real pre-execute waterfall — not prompts beside the tools. The loop guard, the gates, the approval ladder, confinement, evidence and the record. The learn page walks each station.

Anatomy of one tool call. The same path carries secret disclosure, mount grants, the egress proxy and the record.
